🚀 0. Hướng dẫn nhanh khi chuyển sang máy tính khác

Khi di chuyển dự án WebQLCHCF sang một máy tính mới, cần tuân thủ nghiêm ngặt các bước cấu hình môi trường dưới đây để đảm bảo ứng dụng vận hành chính xác và kết nối thành công tới cơ sở dữ liệu.

0.1 Yêu cầu môi trường hệ thống

Thành phần Phiên bản / Yêu cầu tối thiểu Vai trò trong hệ thống
Hệ điều hành Windows 10 / 11 Môi trường triển khai và chạy thử nghiệm cục bộ.
.NET SDK .NET SDK 10.0 (Target Framework: net10.0) Trình biên dịch và chạy ứng dụng ASP.NET Core.
DBMS SQL Server 2019 / 2022 (Express, Developer hoặc Enterprise) Hệ quản trị cơ sở dữ liệu quan hệ lưu trữ toàn bộ dữ liệu.
Công cụ quản trị SQL Server Management Studio (SSMS) v18+ hoặc Azure Data Studio Thực thi script SQL, quản lý bảng, trigger và stored procedure.
IDE Visual Studio 2022 (v17.12+) hoặc VS Code (kèm C# Dev Kit) Môi trường phát triển và gỡ lỗi mã nguồn C#.

0.2 Quy trình thiết lập cơ sở dữ liệu bằng SQL Server

  1. Mở SSMS và kết nối tới SQL Server instance cục bộ (ví dụ: localhost hoặc .\SQLEXPRESS).
  2. Mở file script SQL chính là QLCHCF.sql tại thư mục gốc của dự án.
    ⚠️ CRITICAL REQUIREMENT

    File QLCHCF.sql nằm ở thư mục gốc là file cơ sở dữ liệu chính thức và duy nhất của dự án. Không sử dụng file QLCHCF_Full.sql vì đó không phải là file chính thức hiện tại của đồ án.

  3. Xử lý cơ sở dữ liệu đã tồn tại:
    • Nếu trên SQL Server đã có database tên là QLCHCF, hãy tiến hành sao lưu nếu cần thiết, sau đó drop database cũ:
      SQL
      USE master;
ALTER DATABASE QLCHCF SET SINGLE_USER WITH ROLLBACK IMMEDIATE;
DROP DATABASE QLCHCF;
    • Chạy lại toàn bộ script QLCHCF.sql để tạo mới database cấu trúc chuẩn.
  4. Kiểm tra tính toàn vẹn của Database:
    • Refresh Object Explorer trong SSMS và kiểm tra database QLCHCF.
    • Đảm bảo hệ thống đã tạo đủ 17 bảng chính bao gồm: Ban, KhachHang, KhuyenMai, LoaiSP, NhanVien, TaiKhoan, SanPham, HoaDon, CTHD, ThanhToan, NguyenLieu, CongThuc, PhieuNhap, CTPN, ChamCong, Luong, AuditLog.
    • Đảm bảo các Stored Procedure cốt lõi đã tồn tại đầy đủ trong thư mục Programmability > Stored Procedures (ví dụ: TaiKhoan_DangNhap, ChamCong_CheckIn, ChamCong_CheckOut, ThanhToan_TienMat, ThanhToan_TaoQR, ThanhToan_XacNhanQRTheoPhien, Ban_KhachDi, AuditLog_Them,...).

0.3 Cấu hình chuỗi kết nối trong appsettings.json

File cấu hình liên kết ứng dụng với cơ sở dữ liệu nằm tại appsettings.json. Tùy thuộc vào cấu hình SQL Server trên máy mới, hãy chỉnh sửa giá trị Server trong connection string:

  • Trường hợp dùng SQL Server mặc định (Default Instance / Developer / LocalHost):
    JSON
    "ConnectionStrings": {
  "DefaultConnection": "Server=localhost;Database=QLCHCF;Trusted_Connection=True;TrustServerCertificate=True;"
}
  • Trường hợp dùng SQL Server Express (SQLExpress Instance):
    JSON
    "ConnectionStrings": {
  "DefaultConnection": "Server=.\\SQLEXPRESS;Database=QLCHCF;Trusted_Connection=True;TrustServerCertificate=True;"
}
⚠️ WARNING

Tên của connection string bắt buộc phải giữ nguyên là DefaultConnection vì Program.cs đang đọc cấu hình trực tiếp từ key này. Luôn giữ TrustServerCertificate=True để tránh các lỗi kết nối SSL trên môi trường local.

0.6 Các lỗi thường gặp và phương pháp khắc phục nhanh

🔧 Xem danh sách lỗi & cách khắc phục
  • Lỗi: SqlException (0x80131904): Cannot open database "QLCHCF"...
    • Nguyên nhân: Database QLCHCF chưa được tạo hoặc chưa chạy script.
    • Khắc phục: Mở SSMS, kết nối tới Server, mở file QLCHCF.sql và chạy toàn bộ script.
  • Lỗi: A connection was successfully established... error during pre-login handshake.
    • Nguyên nhân: Thiếu TrustServerCertificate=True trong chuỗi kết nối.
    • Khắc phục: Sửa appsettings.json, thêm ;TrustServerCertificate=True vào cuối chuỗi.
  • Lỗi: System.InvalidOperationException: Unable to resolve service for type 'AppDbContext'...
    • Nguyên nhân: Cấu hình đăng ký DbContext bị lỗi hoặc connection string trống.
    • Khắc phục: Kiểm tra tên key DefaultConnection trong appsettings.json có khớp 100%.
  • Lỗi: WebQLCHCF.exe process is locked
    • Nguyên nhân: Tiến trình web cũ đang chạy ngầm.
    • Khắc phục: Mở Task Manager, kết thúc tiến trình hoặc gõ taskkill /f /im WebQLCHCF.exe.

📋 1. Tổng quan dự án

  • Tên dự án: WebQLCHCF (Hệ thống Web Quản Lý Cửa Hàng Cà Phê).
  • Mục tiêu: Xây dựng giải pháp quản lý bán hàng, vận hành và nhân sự dành cho quán cà phê vừa và nhỏ. Hỗ trợ POS bán hàng tại quầy, quản lý bàn linh hoạt, tích hợp thanh toán VietQR động, chấm công tự động, tính lương, kiểm soát tồn kho và ghi vết Audit Log.
  • Công nghệ cốt lõi: ASP.NET Core MVC (.NET 10.0), Entity Framework Core, SQL Server, Stored Procedure, Bootstrap 5, Javascript, CSS3.
  • Database chính: QLCHCF (khởi tạo bởi script QLCHCF.sql).
  • Phân hệ chính:
    1. Quản lý Bán hàng (Order & POS): Lập hóa đơn, chọn món, áp dụng khuyến mãi, tích điểm, chọn bàn trống, hỗ trợ mang về.
    2. Quản lý Thanh toán: Tiền mặt, VietQR động tự sinh kèm đếm ngược 15 phút, mock webhook xác nhận.
    3. Quản lý Vận hành quán: Sơ đồ bàn vật lý (Trống, Đang phục vụ), bàn ảo mang về (MVE).
    4. Quản lý Danh mục: CRUD Sản phẩm, Loại SP, Khuyến mãi, Khách hàng.
    5. Quản lý Kho & Công thức: Nguyên liệu, Công thức pha chế, Phiếu nhập kho, kiểm soát tồn kho.
    6. Nhân sự & Chấm công: Hồ sơ NV, tài khoản phân quyền, auto check-in/out, tính lương tháng.
    7. Thống kê & Giám sát: Dashboard, doanh thu, Audit Log real-time.
  • Trạng thái: Dự án tích hợp động với DB SQL Server qua Stored Procedure. Toàn bộ POS, QR VietQR, phân quyền Action và Audit Log hoạt động ổn định.

🔧 2. Công nghệ và lý do sử dụng

Dự án chọn lựa các công nghệ hiện đại, ổn định và phù hợp nhất:

Xem chi tiết công nghệ
  • ASP.NET Core MVC (.NET 10.0): Cấu trúc MVC phân tách rõ ràng, middleware mạnh, tối ưu bộ nhớ và tốc độ, Routing linh hoạt và Session bền vững.
  • Razor Views & Bootstrap 5: Razor trộn C# vào HTML để render động phía Server (SSR), Bootstrap 5 + Bootstrap Icons phát triển UI responsive mà không phụ thuộc jQuery.
  • Entity Framework Core (EF Core): ORM hướng đối tượng an toàn, tự động cấu hình ánh xạ FK và composite key. Cầu nối gọi stored procedure qua ADO.NET hoặc SQL Interpolated.
  • SQL Server & Stored Procedure: DBMS độ tin cậy cao, toàn vẹn dữ liệu qua Constraints/FK. Logic nghiệp vụ nặng đóng gói trong SP nhằm đẩy tốc độ xử lý về DB, giảm thiểu độ trễ mạng.
  • Cơ chế Session: Lưu trạng thái phiên đăng nhập (MaTK, MaNV, TenNV, VaiTro, TenDangNhap).
  • PJAX & JavaScript: PJAX cập nhật động nội dung chính bằng AJAX + pushState, giỏ hàng POS phía client, bộ đếm ngược QR thời gian thực.
  • Audit Log Engine: Ghi nhận sự kiện nghiệp vụ quan trọng giúp kiểm soát rủi ro thất thoát.
  • VietQR Demo Integration: API img.vietqr.io sinh QR chứa mã ngân hàng, số tiền, nội dung chuyển khoản tự động.

🏛️ 3. Kiến trúc tổng thể

Hệ thống thiết kế theo kiến trúc 3 tầng (3-Layer Architecture) kết hợp MVC chuẩn ASP.NET Core:

Kiến trúc phân tầng
[Browser / Client]
        │ (HTTP Request / AJAX / PJAX)
        ▼
[Middleware Pipeline] (Routing -> Session -> RoleAuthorize Filter)
        │
        ▼
[Controllers] (AccountController, OrderController, SanPhamController,...)
        │
        ├───► [ViewModels / InputModels] (Validate, nhận dữ liệu form)
        │
        ▼
[Services Layer] (OrderService, ChamCongService, DashboardService, AuditLogService)
        │
        ├───► [AppDbContext] (Cầu nối mapping C# Entity và Stored Procedure)
        │            │
        │            ▼ (LINQ / Raw SQL / ExecuteSqlInterpolated)
        └──────► [SQL Server Database] (Tables, Views, Persisted Computed Columns, Stored Procs)
                     │
                     ▼ (Dữ liệu trả về / Output Params / Result Set)
[Razor Views] ◄──────┴
        │ (Render HTML + CSS + JS)
        ▼
[Browser / Client] (Hiển thị UI/UX Premium, countdown QR, live charts, sidebar collapse)

Cơ chế luồng hoạt động:

  1. Client / Trình duyệt: Người dùng tương tác gửi HTTP request (GET/POST) hoặc kích hoạt PJAX.
  2. Middleware Pipeline: Request đi qua Routing, Session và RoleAuthorizeAttribute. Nếu chưa đăng nhập hoặc sai vai trò, redirect ngay.
  3. Controllers Layer: Tiếp nhận, kiểm tra ModelState.IsValid, chuyển tiếp xuống Service.
  4. Services Layer: Logic nghiệp vụ: tính toán lương, chuẩn bị hóa đơn, tích điểm, gửi truy vấn DB.
  5. AppDbContext & Database: Gọi LINQ/SQL/SP qua EF Core. SQL Server xử lý, kích trigger, cập nhật Computed Column, trả kết quả.
  6. Razor Views: Controller nhận kết quả, kết hợp ViewModel, render HTML+CSS+JS gửi về client.

⚡ 4. Program.cs hoạt động như thế nào

File Program.cs là Entry Point của ứng dụng web, khởi dựng cấu hình dịch vụ (Services Configuration) và thiết lập Middleware Pipeline.

4.1 Khởi tạo dịch vụ và Dependency Injection (DI)

Program.cs
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();
builder.Services.AddSession();
builder.Services.AddHttpContextAccessor();
  • AddControllersWithViews(): Đăng ký dịch vụ MVC (Controllers, Razor Engine, Model Binding, Validation).
  • AddSession(): Đăng ký quản lý Session cục bộ.
  • AddHttpContextAccessor(): Cho phép các lớp thuần C# (như AuditLogService) truy cập thông tin request hiện tại.
Program.cs
builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlServer(builder.Configuration.GetConnectionString("DefaultConnection"))
);
Program.cs
builder.Services.AddScoped<IDashboardService, DashboardService>();
builder.Services.AddScoped<IOrderService, OrderService>();
builder.Services.AddScoped<IChamCongService, ChamCongService>();
builder.Services.AddScoped<IAuditLogService, AuditLogService>();

Đăng ký DI theo phạm vi Scoped (một thực thể/HTTP request): IDashboardService, IOrderService, IChamCongService, IAuditLogService.

4.2 Thiết lập Middleware Pipeline

Program.cs
var app = builder.Build();
await WarmUpEfCoreAsync(app);

if (!app.Environment.IsDevelopment()) {
    app.UseExceptionHandler("/Home/Error");
    app.UseHsts();
}
app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseSession();      // PHẢI ĐẶT TRƯỚC UseAuthorization
app.UseAuthorization();
⚠️ MIDDLEWARE SEQUENCE

Thứ tự Middleware bất di bất dịch:

  • UseSession() bắt buộc TRƯỚC UseAuthorization(). Nếu ngược lại, RoleAuthorizeAttribute không đọc được Session → lỗi vòng lặp redirect vô tận.
  • UseStaticFiles() phục vụ file tĩnh CSS/JS/ảnh từ wwwroot mà không đi qua MVC.

4.3 Định tuyến hệ thống (Routing Configuration)

Program.cs
app.MapControllerRoute(name: "controller-default", pattern: "{controller}/{action=Index}/{id?}");
app.MapControllerRoute(name: "default", pattern: "{controller=Account}/{action=Login}/{id?}");
  • Route chung: Cấu trúc URL chuẩn MVC, mặc định action Index.
  • Route mặc định: Trang chủ khởi tạo = AccountController > Login, buộc mọi người dùng qua đăng nhập.

4.4 Cơ chế Warm-up EF Core khi khởi động

Program.cs
static async Task WarmUpEfCoreAsync(WebApplication app)
{
    try {
        using var scope = app.Services.CreateScope();
        var context = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        _ = context.Model.GetEntityTypes().Count();
        await context.Database.CanConnectAsync();
    } catch (Exception ex) {
        app.Logger.LogWarning(ex, "Không thể warm-up EF Core.");
    }
}
  • Mục đích: Khắc phục Cold Start của EF Core. Biên dịch mapping metadata sẵn khi web khởi động.
  • Giải pháp: Gọi đếm entity + CanConnectAsync. Request đầu tiên sẽ nhanh hơn. Nếu lỗi chỉ ghi warning, không crash ứng dụng.

    .ValueGeneratedOnAddOrUpdate()

8.1 AppRoles.cs — Hằng số vai trò

8.2 Custom Authorization Filter — RoleAuthorizeAttribute.cs

RoleAuthorizeAttribute.cs
public override void OnActionExecuting(ActionExecutingContext context)
{
    var session = context.HttpContext.Session;
    var maTK = session.GetString("MaTK");

    // 1. Kiểm tra đăng nhập
    if (string.IsNullOrWhiteSpace(maTK)) {
        context.Result = new RedirectToActionResult("Login", "Account", null);
        return;
    }

    // 2. Nếu không chỉ định vai trò, chỉ cần đăng nhập
    if (_allowedRoles.Count == 0) { base.OnActionExecuting(context); return; }

    // 3. Kiểm tra vai trò
    var vaiTro = session.GetString("VaiTro");
    if (string.IsNullOrWhiteSpace(vaiTro) || !_allowedRoles.Contains(vaiTro.Trim())) {
        context.Result = new RedirectToActionResult("AccessDenied", "Account", null);
        return;
    }
    base.OnActionExecuting(context);
}

AccessDenied: Gõ URL trực tiếp vào route bị chặn → redirect về 403 Forbidden.

8.3 Phân quyền Session & Role

  • Client (UI/UX): Layout đọc Session.GetString("VaiTro") để ẩn/hiện menu sidebar theo vai trò.
  • Server (Logic chốt chặn): [RoleAuthorize(AppRoles.QuanLy)] trên Controller/Action. Gõ URL trực tiếp vẫn bị chặn hoàn toàn.

16.5 Luồng POS Mang về

  • Chọn "Mang về" → gán bàn ảo MVE.
  • Không thay đổi bàn vật lý, không cần dọn/trả bàn.

16.6 Thanh toán Tiền mặt

  • Tại Receipt, chọn "Tiền mặt". Gọi ThanhToan_TienMat.
  • Hóa đơn → HoanThanh / DaThanhToan / TienMat.
  • Bàn vật lý giữ nguyên Đang phục vụ để nhân viên dọn dẹp trước.

16.7 Thanh toán VietQR động

1
Chọn "QR"

2

16.8 Sửa món khi chờ QR

  • Click "Sửa order" → ThanhToan_SuaOrder: hủy phiên QR cũ, chuyển về sửa món, bàn giữ nguyên.
  • Redirect về POS /Order/Create?editMaHD=... tải lại giỏ hàng cũ.

16.9 Hủy hóa đơn chưa thanh toán

  • Click "Hủy hóa đơn" + nhập lý do → ThanhToan_HuyOrder.
  • Hóa đơn → DaHuy. Bàn vật lý tự động trả về Trống ngay lập tức.

16.10 Xử lý hết hạn phiên QR

  • Countdown về 0 hoặc quét định kỳ ThanhToan_XuLyTatCaQRHetHan:
  • Phiên QR → HetHan. Hóa đơn → DaHuy. Bàn vật lý tự động trả Trống (chỉ áp dụng Tại quán).

16.11 Khách đi & Trả bàn thủ công

  • Khách thanh toán xong + ra về. NV dọn dẹp → click "Trả bàn".
  • Gọi Ban_KhachDi: bàn → Trống. Ghi Audit Log.
  • Ràng buộc: Nếu còn hóa đơn chưa thanh toán, hệ thống ngăn trả bàn.

🌐 18. Web động và mức độ dữ liệu thật

  • Mức độ tích hợp: Phần lớn dữ liệu nghiệp vụ truy vấn động từ SQL Server. Đánh giá khoảng 96–98/100 điểm kỹ thuật.
  • Các mô-đun dữ liệu thực: POS, Hóa đơn, SP, Bàn, KM, Dashboard, AuditLog, Chấm công, Lương hoạt động trực tiếp trên DB thật qua SP và EF Core.
  • Hằng số nghiệp vụ hợp lệ: Mã bàn ảo MVE, trạng thái ChoThanhToan/DaThanhToan trong OrderWorkflowConstants, cấu hình VietQR, text nhãn UI — là hằng số kiến trúc hợp lệ.

⚠️ 19. Giới hạn hiện tại

  • Plain-text Password: Mật khẩu demo lưu văn bản thuần. Cần mã hóa (BCrypt/Argon2/PBKDF2) trước khi vận hành thực tế.
  • Độ phức tạp tài khoản mẫu: Tài khoản seed đơn giản (pv_tu, 12345678), chưa đạt tiêu chuẩn SRS đầy đủ. Màn hình ChangePassword đã có validation mạnh hơn.
  • Webhook VietQR: Đang là Demo (nút bấm giả lập). Thực tế cần tích hợp API ngân hàng + Webhook biến động số dư.
  • Trừ tồn kho tự động: Chưa trừ kho âm tức thời tại transaction POS để tránh khóa bảng khi đông khách.
  • Audit Log Fault Tolerance: Ghi log sau nghiệp vụ chính. Nếu lỗi → chỉ Warning, không rollback bán hàng.
  • Chuyển đổi máy: Cần cập nhật Server trong connection string appsettings.json.
